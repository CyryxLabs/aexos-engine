## Architecture decisions

1. **Separate deployment.** Use a private `apps/dashboard` package with plain JavaScript, existing static Office modules/assets, Vercel Node HTTP functions, Supabase Auth and Postgres. Do not bundle the app, migrations, cloud credentials, deployment files or test captures into the public Core npm TGZ. No new rendering framework or visual world is required.
2. **CLI first and npm accessible.** Ship a Node built-in-only outbound bridge and shared schema under `.aexos-core/core/virtual-office/cloud/`, exposed through a narrow `office connect` subcommand. It starts the existing local Office through its exported `cli.run`/`createVirtualOfficeServer` seam for one canonical `--project-root`, then reads that owned instance's projector. Verify the returned canonical root/project identity. Do not attach to an arbitrary localhost port and infer project identity from a basename: current `/health` and `/api/snapshot` are not an authenticated root-binding handshake. An occupied collector port fails with guidance; no silent attachment to another project.
3. **Do not widen the local collector.** Preserve `host-bridge.submitEvent()` loopback-only HTTP enforcement, local producer-token semantics, Host checks and same-origin policy. The cloud bridge is a separate outbound HTTPS client. The hosted browser never contacts loopback, receives the local producer token, or sends execution commands.
4. **Narrow remote representation.** Map the local projector into a new versioned metadata-only transport schema. Never upload `getSnapshot()` wholesale: it contains project basenames, descriptions, task text and public messages. Both bridge and ingest validate an exact allowlist. Catalog labels/assets come from the reviewed static UI; arbitrary project source text never becomes display markup.
5. **Two separate credentials.** An authenticated owner session grants read access to that owner's project data. A distinct 256-bit random ingest credential grants write-only telemetry for exactly one pre-provisioned project. Store only its SHA-256 digest server-side and compare safely. Deliver the raw credential to the CLI through a masked interactive TTY prompt or explicitly named process-only `AEXOS_DASHBOARD_INGEST_TOKEN`; consume it into memory and remove the process environment entry before child creation. Never put it in argv, URLs, logs or disk. Nonsecret remote project/root binding may use flags/config. It is not the local Office token and cannot read snapshots, change ownership, authenticate a user or execute work.
6. **Durable data, separated server authority.** Supabase holds project ownership, ingest credential digests, latest accepted snapshot and bounded telemetry history. No function-local memory or filesystem is durable state. Vercel Node BFF handles secure HttpOnly user sessions and owner reads using the verified user's JWT and RLS. Owner setup/rotation calls the fixed public RPC with that user JWT; private fixed Postgres-owner definers derive ownership from the live caller and accept no caller-supplied owner identity. Supabase Edge uses privileged runtime credentials only for ingest-token lookup and the atomic ingest RPC. Never retrieve/extract these secrets through tooling or expose them to Vercel/browser clients. The atomic token-validation/persistence RPC is executable only by the privileged ingest role, with PUBLIC/anon/authenticated execution revoked; it resolves project/owner/epoch from the credential, never body-supplied ownership. Session validation is described below.
7. **Bounded live polling.** Start with a five-second bridge/browser poll interval, one in-flight request, bounded backoff and no persistent Vercel process/WebSocket dependency. Preserve observation timestamps and evidence classes. A new receipt timestamp proves transport availability, not continuing agent activity. Refreshing a historical snapshot must not renew agent liveness. Display stale/offline and last accepted observation honestly.

## Shared transport and frontend contract v1

The portable ESM `cloud/schema.mjs` has no Node-specific imports. Node and Edge execute the same validator; the Edge build copies it with a byte-equality check. Every record rejects unknown keys. Numbers are finite safe integers; producer observation timestamps (`observedAt`, `lastSeen`, event `timestamp`) are positive Unix milliseconds. API/database receipt fields (`lastReceivedAt` and `cloud.receivedAt`) are ISO strings or null. Project/epoch IDs are UUIDs; opaque source identifiers are SHA-256 lowercase hex of a domain-separated project/epoch/source identifier. Never transmit raw arbitrary identifiers. `agentKey` is a key from the reviewed static catalog or null, never a freeform alias.

```text
Envelope = {schemaVersion:1, projectId, epoch, sequence, observedAt,
            sessions:[Session], events:[Event], omitted:{sessions,events}}
Session = {id, agentKey, host, state, lastSeen, evidence}
Event = {id, sessionId, agentKey, type, state, timestamp, host, evidence}
```

`sequence` starts at 1 and is monotonic within an owner-issued epoch. `omitted` counts are nonnegative safe integers. Session IDs and event IDs are hashes; event sessionId is the exact mapped projected session hash or null when no mapping exists. Differently hashed source session IDs must not imply a false join. Event state may be null; session state is required. State enum is `available|assigned|running|waiting|blocked|completed|failed|stale|offline`. Host enum is `cli|codex|chatgpt|claude-code|grok|gemini|unknown`. Evidence enum is `runtime|manual|test|unavailable`; unrecognized/absent provenance becomes unavailable and must never be promoted to runtime. Event type is exactly one of the 21 existing `ACCEPTED_EVENT_TYPES` in `event-normalizer.js`; no message content accompanies collaboration events. Retain observation timestamps from the projector; upload time must not replace lastSeen. Unknown/unmapped agents become null and cannot invent catalog entries. Identifiers/catalog keys are bounded to 128 ASCII characters; hashes are exactly 64 hex characters. Limits and freshness rules are those in AC5/AC6.

| Same-origin route | Request / response |
| --- | --- |
| GET `/api/session` | `{authenticated:boolean,user:{id,email}|null}`; unauthenticated state contains no project data |
| POST `/api/login` | `{email,password}`; verified session sets Secure HttpOnly SameSite cookie; returns session shape without JWT |
| POST `/api/activate` | Exactly `{accessToken,password}` from a human-submitted invite/recovery form. The access token is accepted only from the implicit fragment, stripped immediately from browser history, retained in memory only, and cleared on completion or abort. The BFF verifies the same live non-anonymous identity before and after a password-only Auth update, then issues the existing Secure HttpOnly session cookie. Password length is 12–1024 and confirmation must match; pending activation disables the abort/return control. |
| POST `/api/logout` | `{}`; revoke current Supabase session, clear cookie and private UI state; fail closed if revocation cannot be confirmed |
| GET `/api/projects` | `{projects:[{id,label,connected,lastReceivedAt}]}` for owner only; `lastReceivedAt` is an ISO string or null |
| POST `/api/projects` | `{label}`; owner setup creates `{project:{id,label,epoch},ingestToken,epoch,ingestUrl,origin,expiresAt}`; token returned once, never cached/persisted in browser |
| POST `/api/projects/:id/token` | `{}`; owner-only rotation returns `{ingestToken,epoch,expiresAt}`, durably revoking previous token/epoch |
| GET `/api/catalog` | Reviewed static Office catalog/world only, no private activity; requires the same verified live session as other private reads |
| GET `/api/snapshot?projectId=<uuid>` | Office-compatible snapshot described below; 401 unauthenticated, 404 inaccessible/nonexistent project without existence disclosure |

All mutation routes require same-origin/CSRF checks. The BFF calls the fixed owner-management RPC with the user's verified JWT; only the Edge ingest function uses privileged runtime credentials. Edge HTTPS `/functions/v1/aexos-telemetry/ingest` accepts Envelope and a Bearer ingest token, returns bounded `{accepted:true,sequence}` after the atomic write. It is not a browser execution API. The outbound bridge pins the configured HTTPS destination (scheme, host, port and exact path), separately validates the declared HTTPS Origin, never follows redirects, and never logs token or auth bodies.

The snapshot response uses existing keys `{version:1,sourceScope:'project',generatedAt,project,registryVersion,squadCount,agentCount,counts,squads,sessions,hosts,messages:[],events,heartbeatTtlMs:30000,cloud}`. `project` is the owner's explicit remote label, never the local basename. The app-owned pinned catalog supplies reviewed squad/agent names, descriptions, IDs and assets from the existing primary registry; Core ships only the reviewed catalog-key allowlist. No dynamic project catalog is uploaded. Agent state is derived from accepted sessions using the existing projector precedence; include observed boolean and lastSeen, with task/storyId/phase/toolName/command/pid null. Events contain only validated metadata plus static catalog labels; messages remain empty. No raw spread of local snapshot/data is allowed. `cloud={projectId,receivedAt,connectionState,sequence,omitted}`; connectionState is `never-connected|connected|offline`, `receivedAt` is an ISO string or null, and sequence is 0 before first acceptance. Stale agent state is derived independently of bridge connectivity. Before first ingestion, return the static roster all offline/unobserved and empty sessions/events, not sample activity. Poll every five seconds with bounded backoff; no new SSE dependency. History is the bounded accepted event collection within this snapshot, so no separate history route is needed.

### Session revocation boundary

JWT verification and Supabase `getUser` are necessary but do not alone prove a session remains active after logout. Every private API read and direct database RLS policy also requires a live session predicate matching the verified JWT `session_id` to `auth.sessions.id` and `auth.sessions.user_id = auth.uid()`, rejecting absent/malformed claims or rows. Do not authorize using user_metadata. A minimal helper may be SECURITY DEFINER only in a private non-exposed schema, with fixed empty search_path, fully qualified relations, no dynamic SQL, no caller-supplied identity, and revoked PUBLIC/anon execution. Prefer a narrow non-login owner when the managed platform supports the required access. Actual platform tests on this project showed custom roles could not read the managed auth.sessions relation (RLS enabled with no policies); the supported bounded implementation may instead use the existing postgres owner for exactly session_live and manage_project. This does not grant clients or custom roles postgres membership, superuser or BYPASSRLS. session_live has no arguments and returns only the current verified caller/session validity boolean. manage_project must check that live session before any work, derive ownership solely from auth.uid(), select an owned project FOR UPDATE before rotation, constrain insertion to that owner, serialize the owner quota/rotation, and use fixed SQL only. Its definer bypass is restricted by those explicit owner predicates; public API reads still use owner/session RLS. No arbitrary relation, SQL, identity or privilege parameter is permitted. Do not try to obtain unavailable managed-auth grants by broadening role memberships. Grant only required authenticated execution for RLS; expose no auth.sessions rows. An authenticated, security-invoker wrapper may return only the caller's boolean validity for the BFF. Prove cross-user/session denial and post-logout denial through the direct API as well as the BFF. Ingest service RPC authorization is separate and does not rely on auth.uid(); service_role-only grants and token/project/epoch validation enforce that boundary. Service secrets remain solely runtime-injected in Edge.

## 2026-10-26 implementation and verification record

The private dashboard package, four-file Core cloud transport, narrow `office connect` CLI dispatch, BFF, Edge ingest handler, schema/RLS, existing-Office UI reuse, and password activation/recovery completion are implemented. The activation path accepts only implicit-fragment `type=invite|recovery`, strips the entire fragment before interaction, keeps the token in memory only, submits exactly `{accessToken,password}` after human confirmation, verifies a live non-anonymous identity before and after a password-only update, and issues the existing secure HttpOnly cookie only after that verification. Completion and idle abort clear the token/form; while submission is in flight, Return to sign in is disabled so an aborted view cannot race into a later silent session bootstrap.

Local evidence records 36 native app tests. Actual approved-project verification records 25 REST/Auth/RLS/ingest checks covering authentication and session liveness, cross-owner/anonymous denial, ingest and ordering boundaries, logout/revocation, test-user deletion, zero residual database rows, and the version-6 helper tombstone. The inspected database surface contained five function bodies, four RLS policies, 23 columns and nine indexes. Migration history for version `20261026161848` was repaired with zero SQL statements executed during the history repair; this is not evidence of a fresh schema bootstrap. The separately verified package/source guards keep `apps/dashboard/**` private and excluded from the public Core TGZ, and the existing local Office regression remained passing.

This record does not create the first owner. No default password was generated and no invitation was sent. Preview and REST/database boundaries are verified, but first-owner browser/BFF use, real CLI-to-hosted observation, and authenticated responsive, keyboard, reduced-motion and accessibility acceptance remain open. Existing Office assets and Cyryx visual direction were retained. No owner email or private evidence bytes belong in this public story.
