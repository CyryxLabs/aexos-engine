## Verified structure and reusable implementation

The application remains a Node.js/CommonJS CLI framework with Jest tests, YAML configuration and plain JavaScript/CSS office UI. The configured Next.js preset is a preference for generated projects, not evidence that the installer or office uses Next.js. Runtime modules live under `.aexos-core/core/`; installer under `packages/installer/src/wizard/`; canonical agent/task definitions under `.aexos-core/development/`; squads under `squads/`. The task template's `infrastructure/services/` directory does not exist in this checkout, so introducing a parallel services hierarchy is unnecessary.

Existing office modules are `cli.js`, `server.js`, `config-loader.js`, `registry-loader.js`, `event-normalizer.js`, `state-projector.js` and `public/*` in `.aexos-core/core/virtual-office/`. They already offer a loopback HTTP collector, bounded JSON request bodies, normalization/redaction, state TTL, snapshots, SSE and layered agent rendering. `core/events/dashboard-emitter.js` sends CLI telemetry to `AEXOS_MONITOR_URL` or port 4001 and writes a fallback JSONL file on failure. This is a useful foundation; the office is not literally just a static image, but its cross-host integration and persistence are incomplete.

Master orchestrates work; `AgentRuntime` adds governance, declared capability lease checks and result normalization. Existing `capability-broker.js`, `outcome-verifier.js` and `durable-mission.js` should remain the execution foundation. An office adapter must not become another orchestrator or independently execute work.

## Bounded implementation architecture

Use the existing local collector as the single observation transport. Add a CLI bridge usable by CLI, Codex, Claude Code, Gemini and Grok host processes. ChatGPT can participate only when an explicitly configured connector/bridge can reach this local service; a browser conversation does not automatically expose its activity to the repository. An accepted manually submitted event proves ingestion, not native host integration.

The envelope should add `schemaVersion`, stable `id`, `projectId`, allowlisted `host`, `sessionId`, `runId`, `agentId`, `squadId`, event type, producer timestamp and received timestamp. Public message events add sender/recipient identity and correlation ID. Keep summary text bounded and redacted; never ingest raw tool arguments, terminal output, secrets or hidden reasoning by default. Accept legacy field spellings through explicit compatibility normalization, not arbitrary field copying. Replay must recognize already normalized records rather than losing camelCase fields on a second normalization pass.

Session identity is `(projectId, host, sessionId, agentKey)`; runs belong to sessions. Track start, heartbeat, tool/command start, completion, failure, blocked, waiting, message and end. Unknown agents appear as unresolved events and do not silently impersonate a catalog agent. Enforce source ordering and duplicate IDs; producer clocks must not allow old sessions to overwrite newer ones. Snapshot fields for hosts/sessions/messages are additive to existing squad/agent counts. Legacy agent events remain visible with explicit unknown host identity.

Provide CLI equivalents for observation: snapshot/status JSON and bounded event submission from stdin/file with clear validation errors. Keep server mode backwards compatible. Automatic hooks should call the same bridge with a short bounded timeout and nonfatal telemetry failure; offline delivery uses a project-confined queue. Browser reconnect obtains a full snapshot before applying deltas. The UI has no dispatch, approval or provider credential authority; user actions can inspect sessions, filter, search, select agents and copy CLI commands. Actual execution remains Master-led CLI work.

For a collaboration message, distinguish `observed` from `delivered` and `acknowledged`. A timeline entry is not proof that another host received a message. Cross-host routing needs a registered recipient adapter, explicit authorization, correlation and acknowledgement; disconnected hosts retain an honest undelivered status. Do not implement a fake chat interface claiming delivery through telemetry alone.

## Visual and installation design direction

Reuse the office DOM/SSE foundation with a responsive workspace: host connection rail, scalable team rooms, consistent vector/CSS agent identities, selected-agent/session inspector and readable event/message timeline. The lead's current screenshot inspection confirms a giant background with tiny poorly fitted agent overlays and unreadable abbreviated labels. Prefer true DOM spatial room cards with readable names and consistently scaled initials/vector identities; do not retain fake roaming. A campus background can be decorative, while operational text and identities remain crisp at every viewport. Provide keyboard selection, visible focus, empty states, stale connection treatment and reduced motion. Animations reflect observed transitions; idle movement must not imply execution. Show same agent with multiple host sessions without overlapping sprites or loss of identity.

Installer improvements should preserve the existing prompts, defaults, noninteractive operation and entitlement flow. Use a compact progress hierarchy, clear target directory/version/profile/IDE summary, understandable validation errors and an actionable final command list. Respect terminal width, no-color and non-TTY output. Do not bundle an unrelated web framework or replace CLI installation just for appearance. Verify both success and interrupted/error flows.

## Ownership and gates

Recommended execution slices: runtime owner owns Master/AgentInvoker and regression tests; office backend owner owns collector, normalizer, projector, bridge/CLI and tests; UI owner owns office `public/*`; installer owner owns wizard/Doctor and clean-init regression evidence. Coordinate shared entrypoints (`bin/aexos.js`, event emitter, package scripts) explicitly.

Acceptance requires failed-task propagation; two concurrent hosts sharing an agent; fresh/stale/disconnected transitions; journal replay and reconnect; rejected forged/cross-project/malformed events; secret redaction; message correlation without false delivery; CLI-only use; packed clean-install behavior; and desktop/mobile/keyboard visual QA. Run repository lint, typecheck, test and build gates for implementation changes. Provider-native acceptance remains per-host and cannot be inferred from synthetic event tests.

Trade-offs: stdlib HTTP/SSE and JSONL preserve installation simplicity but require bounded queues and explicit durability handling; a new database/broker adds operational burden without resolving missing host adapters. Additive event fields preserve callers but require a careful legacy normalizer. A read-only office respects existing authority and works offline, while actual cross-host delivery remains dependent on authenticated recipient adapters. Architectural analysis is sufficient to start these bounded repairs; broader execution confinement and contract migration remain independently tracked work, not automatically solved by the redesign.
