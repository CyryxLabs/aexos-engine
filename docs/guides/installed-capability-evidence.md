# Installed capability evidence

`aexos capabilities installed --archive=<absolute-core.tgz>` inspects a bounded local npm archive without extracting or executing it. It returns a detached `aexos.installed-capabilities/v1` manifest on stdout. This is artifact inventory, not a runtime or release certificate. Only the current Core Free boundary is supported; other artifacts fail closed.

The manifest includes the compressed artifact hash, exact payload hashes, capability ownership, required paths, license/provenance references, declared runtime dependencies, configuration requirements and evidence exclusions. The embedded catalog and package boundary must match the verifier's trusted versions. Schema validation and regeneration reject altered fields, extra properties, duplicate or aliased archive names, missing content, unowned payloads and prohibited paid squads. License references document inventory; they do not replace a legal review.

To compare a separately installed package, supply `--manifest=<manifest.json>` and `--installed-root=<consumer>/node_modules/@aexos/core` with the same archive. The verifier checks every installed payload file and rejects extra or changed files. Only dependency directories owned by the archive-bound root `package.json` and private `.aexos-core/package.json` are separate from that payload inventory. Other nested `node_modules` locations remain ordinary payload and cannot hide extra files. Both runtime packages receive dependency discovery in `dependencyGroups`; the existing `dependencies` field remains the root-package view. Any unavailable group makes the combined dependency status unavailable. Discovery stays inside that consumer's `node_modules`; global or parent resolution cannot count as installed evidence. Declared entries are resolved and hashed without loading them; this does not validate every transitive dependency byte. `installed-payload-verified` therefore does not prove a successful npm install, dependency execution, an SDLC journey or provider behavior. Inert file-copy tests remain supplemental to the separate actual npm installation receipt.

`--project-root=<ordinary-directory>` adds read-only host evidence. Doctor reports the same distinctions for selected managed hosts. A configuration file yields only `configured-projection`; static parity, installed client identity, native execution and end-to-end acceptance remain `NOT_ASSESSED` without independent receipts. Grok's push authority, compaction digest/wrapper and SYNAPSE engine/wrapper each receive an explicit `NOT_ASSESSED` entry. No host file is modified.

Core Free reports paid content `absent`, with acquisition and activation `NOT_ASSESSED`. The verifier has no activation or entitlement control. Local Pro directories, fixture licenses and a source catalog never establish eligible, installed, activated or customer-acquired paid capabilities. Future distribution adapters require their own authenticated evidence before introducing those states.

Limits: 96 MiB compressed archive, 256 MiB inflated payload, 32 MiB per file, 12,000 entries, 1 MiB per package policy document, 16 MiB manifest. File reads check ordinary paths, single links, bounded actual bytes and descriptor consistency. This read-only verifier does not supply the native Windows publication guarantees required by AEX-4.28.

Current acceptance boundaries: TypeScript, ignore and pg are declared runtime dependencies in Core Free. An initial isolated npm installation loaded the CLI, but its payload verification exposed the internal dependency-directory inventory defect corrected here. Acceptance requires a new archive and actual installed verification of this correction, plus the functional checks for that same artifact. Native Windows publication, authenticated production SOP review, provider execution and complete database reliability have separate evidence requirements. Source tests and archive inspection do not close these holds.
